# Signal

<p class="lede">A signal is a number from 0 to 1, read per subject every frame, that comes from somewhere other than the clock: a pointer, a hover, a meter.</p>

<Signal client:only="react" />

A voice's weight can be a fixed number, or it can be a **signal**: a function the mix calls for each subject every frame, which returns 0 to 1. A signal plugs in at two places only. It can be a voice's `weight`, and it can be the selector `blend` uses to choose between alternatives.

The simplest signal is one you write yourself:

```ts
import type { Signal } from '@msb235/blits';

const ripple: Signal<Bar> = (bar, setting) => 0.5 + 0.5 * Math.sin(setting.timestamp / 400 - bar.i);
bars.cue({ patch: glow, weight: ripple });
```

## Level, slew, lag and gate

`level()` is a signal the host writes. It holds whatever you last `set`, for every subject. In the explainer, the gray line is a level the host sets once a frame from the input you pick.

`slew(of, { riseMs, fallMs })` follows another signal, but no faster than `riseMs` per unit climbing and `fallMs` per unit draining. A tail that dies away is a slew with no rise, and a fade is a slew on a weight. A slew starts on its input the first time it sees a subject; `from` starts it somewhere else, so `from: 0` climbs from rest. Set the fall long and watch the slewed lamp linger after the level drops.

`lag(of, { riseMs, fallMs })` follows too, but exponentially: `riseMs` and `fallMs` are time constants, and after one of them it has covered 63% of the way. It covers the same share of the distance in every equal stretch of time, so it reads the same however the frames are spaced. An exponential never quite arrives, so within `floor` (one millionth by default) it lands on its input, and the subject can come to rest; `floor: 0` keeps the curve exact. It takes `from` as a slew does.

`gate(of, { on, off })` turns a signal into on or off across a band. It switches on when its input reaches `on`, off when it falls to `off`, and between the two it holds whatever it last did. Pick "Steps": the level sits at 0.5, inside the band, twice, and the gate stays where it was each time rather than flickering. A slew can't do that job. It slows a crossing down but still crosses, so an input resting on a threshold drags the slewed value onto the threshold with it.

```ts
import { gate, level, slew } from '@msb235/blits';

const near = level<Bar>();
window.addEventListener('pointermove', (e) => near.set(closeness(e)));

bars.cue({ patch: glow, weight: slew(near, { riseMs: 150, fallMs: 600 }) });
bars.cue({ patch: badge, weight: gate(near, { on: 0.6, off: 0.4 }) });
```

`peak(...signals)` is the loudest of several.

## Only near the pointer: within

A glow around the pointer is a signal read for every subject every frame, though most of them sit at 0. Cue it `within` a circle and the mix reads it only for the subjects inside: it gives every subject outside nothing, without calling the signal for them. The mix needs to know where the subjects are, so the host first calls `plot` with them and their positions, two numbers a subject in one `Float64Array`, `x` then `y`. The mix reads that array in place: to move the subjects, write new positions into it and call `moved`. To move the circle, write to it.

```ts
const xy = new Float64Array(all.length * 2); // x, y for each bar in `all`
all.forEach((b, i) => { xy[2 * i] = b.x; xy[2 * i + 1] = b.y; });
bars.plot(all, xy);

const pointer = { x: 0, y: 0, r: 120 };
const near: Signal<Bar> = (b) => Math.max(0, 1 - Math.hypot(b.x - pointer.x, b.y - pointer.y) / pointer.r);
bars.cue({ patch: glow, weight: near, within: pointer, loop: true });

window.addEventListener('pointermove', (e) => { pointer.x = e.clientX; pointer.y = e.clientY; });
```

The circle declares where the signal is 0; it does not shape it. A signal still above 0 at `r` is cut off there, so outside production the mix checks a few subjects just outside the circle every few frames and warns once if the signal reads above 0 for any of them. It pays while the circle covers a small share of the subjects: on 10,000 subjects a glow over 2% of them costs about a sixth of what it does unbounded, and past about half it costs more. `within` needs a signal `weight`, and is refused with history, `subjects`, a locus, an owner, `from: 'current'`, or a patch that keeps state.

## Where the state lives

A slew or a lag remembers where it was, and a gate remembers which way it last switched. They don't keep that in themselves: they keep it in the mix, through `setting.keep(owner, init)`, once per voice and per subject. So one slew handed to two voices follows twice, independently, and one slew over twelve bars follows twelve times. A stateful signal of your own should keep its state the same way.

A signal marked `input: true` reads something the clock doesn't drive, so its future can't be known ahead of time. `level` is marked, and `slew`, `lag`, `gate`, `peak` and `blend`'s shares inherit the mark from what they read. A signal computed from the clock, like `ripple` above, is not.
