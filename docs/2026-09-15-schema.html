blits · design

An effects schema, and the API around it

A small runtime package for concurrent effects. Each effect runs on its own clock with its own state and weight, and a mix folds them into one value per item per frame by rules that belong to the channel, not the effect.

For: whoever builds blits, and whoever ports klieg, wod, sherpa or magicsmoke onto it. Answers: what the vocabulary is, what an author writes, what a host calls, and where a second engine would plug in.

Design under review · nothing built · 2026-09-15

In one picture

A host steps the mix once a frame. For each item it wants drawn, the mix samples every track that reaches that item, scales each sample toward its channel's rest by the track's current weight, joins them channel by channel, and hands back one offset. The host writes that offset wherever it goes: a three.js mesh, an SVG wedge, a CSS transform, an audio gain.

Everything klieg does today fits this picture, in three copies with three channel sets. wod's transition tracks are the same picture with one item type and a retargeting tween. sherpa's seam is two tracks. magicsmoke's fault is one track whose weight is a signal.

Vocabulary

Ten words. Every other name in the package is built from these.

Offset
A partial record of channel values. A piece writes only the channels it drives; an absent channel means no contribution.
Channel
One field of an offset, with its own arithmetic: how two contributions join, what rest is if there is one, how to scale toward rest, how to lerp.
Table
The channel set for one kind of offset. klieg's pose, klieg's part, wod's presence are each a table.
Item
What is being driven: a letter, a part, a wedge, a page, or a unit value for a system with no item dimension such as klieg's lighting.
Piece
A pure function of normalized time and an item that returns an offset. Optionally stateful. This is klieg's word and it keeps it.
Track
A piece plus its own playback: start, rate, loop, weight envelope, target, and blend options. The unit a host adds and stops.
Mix
The set of live tracks over one table, stepped once a frame and sampled per item. What a host holds.
Signal
A 0..1 scalar resolved per item per frame from something outside the clock: the cursor, a hover value, another track's state.
Handle
What add returns: the live controls on one track, and its completion.
Engine
The implementation behind a mix. One ships. The seam is the mix's own interface.

Channels

The arithmetic of blending is a property of the operand type, so it lives on the channel and nowhere else. Every merge, fade, crossfade, and retarget in the package is one of these four operations.

interface Channel<V> {
  /** Identity. Absent means the channel has none: `color` replaces rather than contributes. */
  rest?: V;
  /** Fold two contributions into one. */
  join(a: V, b: V): V;
  /** Fade toward `rest` by weight 0..1. Required when `rest` is set; absent otherwise. */
  scale?(v: V, w: number): V;
  /** Interpolate, for retargeting and for blending alternatives. */
  lerp(a: V, b: V, u: number): V;
}

type Table<O> = { readonly [K in keyof O]-?: Channel<NonNullable<O[K]>> };

Stock channels cover every case the four repos hold today:

channelrestjoinscalelerpused by
sum()0a + bv · wlinearposition axes, rotation, crawl, yaw, pitch, offset
mul()1a · b1 + (v − 1) · wlineargain, scale, opacity, hold
max()0max(a, b)v · wlineardark, aperture
last()noneb—caller'scolor, offsetAngle
vec(n, ch)per axisper axisper axisper axisVec3 position, premultiplied light

A channel with no rest cannot fade. The mix handles that in one way: below a weight threshold the contribution is dropped, above it the value passes through whole. That is the rule hinge's blend mode already applies to color, and it is stated here once so no consumer rediscovers it. Retargeting is the way a rest-less channel does move smoothly, since a lerp from a sampled value needs no identity.

A table is plain data, so a consumer declares one in a line and the mix is typed by it:

const PART = table<PartOffset>({
  gain: mul(), scale: mul(), dark: max(), crawl: sum(),
  position: vec(3, sum()), rotation: vec(3, sum()),
  light: vec(3, sum()), color: last({ lerp: mixHex }),
});

Pieces

A piece is what an author writes. It is klieg's EffectPiece with two additions: the context carries absolute time as well as normalized, and a piece may declare state.

interface Piece<I, O, S = void> {
  /** Milliseconds per pass. 0 means aperiodic: `t` is always 0 and the piece reads `ctx.elapsed`. */
  duration: number;
  at(t: number, item: I, ctx: Ctx<S>): Partial<O>;

  /** Per-item state, created on the first frame this piece sees an item. */
  state?(item: I): S;
  /** Advances state once per item per frame, before any `at` that frame. `dt` is Infinity under reduced motion. */
  step?(state: S, dt: number, item: I, ctx: Ctx<S>): void;

  /** Present when the piece was authored as keyframes, so an engine that reads data can. */
  readonly keys?: readonly Keyframe<O>[];
}

interface Ctx<S = void> {
  /** The mix clock at this frame. Identical for every sample in the frame. */
  now: number;
  /** Milliseconds since the previous step. Infinity under reduced motion: snap, never integrate. */
  dt: number;
  /** Milliseconds this track has been playing, rate applied. What lets a piece see across passes. */
  elapsed: number;
  /** Which pass this is, 0 first. */
  pass: number;
  /** This track's current weight, so a piece that wants to know how "on" it is can. */
  weight: number;
  /** This item's state, when the piece declares one. */
  state: S;
  /** Anything the host adds for its own pieces: klieg's pointer and pointerInWord go here. */
  host: unknown;
}

Two authoring forms build a piece. Both return the same interface, so a track cannot tell them apart.

formsignaturewhat it is
fnpiece(duration, at, { state?, step? })Procedural. Flicker, roving, a hash walk, a starter strike. Only a JS engine can run one.
keyskeys(duration, stops, { ease?, easeBy?, delayBy? })Declarative stops, klieg's transition sugar and wod's keyframes. Data preserved on piece.keys for an engine that reads data instead of calling functions.

Wrappers stay wrappers. klieg's turns, roving, intermittent, hinge and partition take a piece and return a piece, and none of them changes. Composition at the piece level is for reshaping one contribution; composition at the mix level is for running several. The two do not merge.

Tracks

A track is a piece given a clock and a volume knob. This is the unit that answers "independent state and timeframe": two tracks of the same piece are two clocks, two states, two weights.

interface TrackSpec<I, O> {
  piece: Piece<I, O, any>;
  /** Which items this track reaches. Default: all of them. Resolved once when the track is added. */
  target?: (item: I) => boolean;

  // clock
  /** Mix-clock ms the track starts. Default: the next step. */
  start?: number;
  /** Playback rate. 1 is real time; 0 freezes. */
  rate?: number;
  /** true loops for good, false plays one pass and holds its last value, n plays n passes. */
  loop?: boolean | number;
  /** Per-item phase spread, klieg's stagger grammar. Ramps t; does not offset it. */
  stagger?: number | StaggerSpec;

  // weight
  /** Steady weight, or a signal read per item per frame. Default 1. */
  weight?: number | Signal<I>;
  /** Ramp in and out, ms. Out applies on `stop()` and when a finite loop ends. */
  fade?: { in?: number; out?: number; ease?: Easing };
  /** Tracks sharing a group have their summed weight capped at 1 within it. klieg's phase rule. */
  group?: string;

  // blend
  /** A `keys` piece whose first stop reads "wherever this item is now", lerped over the pass. */
  from?: 'current';
}

interface Handle {
  readonly id: number;
  readonly state: 'pending' | 'live' | 'fading' | 'done';
  /** Live. Writes land on the next step. */
  weight: number;
  rate: number;
  /** Jumps the track's own clock. */
  seek(elapsed: number): void;
  /** Ramps out over `fade.out` unless given a fade here; `at: 'rest'` waits per item for a resting sample first. */
  stop(opts?: { fade?: number; at?: 'rest'; deadline?: number }): void;
  /** Resolves when the track has been removed from the mix, however that happened. */
  readonly done: Promise<void>;
}

Weights are the only knob the mix owns. Fade, crossfade, handover, alternatives, and hinge's continuous mode are all weights over time; the section on blending shows each one as such. A piece never sees a weight applied to its output, it only sees the number in ctx.weight if it cares.

Mix

What a host holds. The methods are few because the tracks carry the options.

function mix<I, O>(table: Table<O>, opts?: MixOptions<I, O>): Mix<I, O>;

interface MixOptions<I, O> {
  engine?: Engine;                // default: mixer
  /** Reduced motion: fades and warm-ups snap, `dt` reads Infinity. Read once at creation, or a signal. */
  reduce?: boolean | (() => boolean);
  /** Merged into every `ctx.host`. */
  host?: unknown;
}

interface Mix<I, O> {
  /** Adds a track. It begins on the next step unless `start` says otherwise. */
  add(spec: TrackSpec<I, O>): Handle;
  /** N tracks whose weights split one signal, k in 0..1. Two pieces crossfade; more make stops. */
  blend(pieces: readonly Piece<I, O>[], by: Signal<I>, spec?: Omit<TrackSpec<I, O>, 'piece' | 'weight'>): Handle[];

  /** Once per frame. Advances every clock, weight and state. Idempotent for a repeated `now`. */
  step(now: number): void;
  /** The merged offset for one item at the stepped frame. `out` is written in place when given. */
  sample(item: I, out?: O): O;
  /** Every channel at rest for this item this frame, so a host can skip the write. */
  atRest(item: I): boolean;

  /** Anything still contributing, fading, or pending. A host stops its loop when this is false. */
  readonly live: boolean;
  /** Stops every track, with the given fade. */
  clear(opts?: { fade?: number }): void;
  /** Forgets per-item state. Call when an item is retired, or let the WeakMap do it. */
  forget(item: I): void;
}

Items are not registered. State lives in a WeakMap keyed by the item object, created on first sample and stepped by the gap in now since that item was last stepped. That is the rule klieg's dwell arrived at, and it means a part a wrapper leaves unasked for a while catches up rather than resuming where it paused.

Signals

A signal is a 0..1 scalar resolved per item per frame. It is the package's one input type from outside the clock, and it plugs in at exactly two places: a track's weight, and blend's selector.

type Signal<I> = (item: I, ctx: Ctx) => number;

// stock combinators; klieg's own `near`, `dwell`, `level` are consumers' signals built on these
function peak<I>(...signals: Signal<I>[]): Signal<I>;          // max
function ease<I>(of: Signal<I>, { riseMs, fallMs }): Signal<I>;  // stateful: climbs and drains toward its input
function level<I>(initial?: number): Signal<I> & { set(v: number): void };  // host-written
function gate<I>(of: Signal<I>, at: number): Signal<I>;          // 0 below `at`, 1 at or above

A stateful signal keeps state the same way a stateful piece does: per item, keyed by identity, stepped by the gap in now. ease is klieg's dwell with the cursor factored out.

Time

  • The mix is pull-based on a host clock. The host owns the frame loop and calls step(now) with milliseconds on any monotonic clock it likes. klieg passes its Clock.now(); wod passes performance.now(); a test passes integers.
  • Everything in a frame reads one now. A second step with the same value is a no-op, and every sample between steps answers from the same frame. This is what makes state advance once however many probes a wrapper makes.
  • A track's clock is (now − start) · rate. Its pass is that modulo duration; both reach the piece, as t and ctx.elapsed. A rate change rebases so elapsed is continuous.
  • dt is derived, never supplied. The gap between this step and the last, per item, and Infinity under reduced motion. A piece that integrates guards against that with a snap, as klieg's already do.
  • Calls land on the next step. A host writes handle.weight or calls stop on its own clock; the mix applies it at the first now that sees it. Nothing changes mid-frame.

Blending

The four behaviors asked for, each as the weight or lerp it reduces to. Nothing here is a mechanism of its own.

behaviorhowwhat it replaces
Fade in and outfade: { in, out } ramps the track's weight; each channel's scale takes it toward rest.klieg's Timeline.weight, the blendMs ramps, and carry.
Crossfade at a phase seamTwo tracks in one group, one fading out as the other fades in. The group caps the summed weight at 1, which is the lurch guard klieg's timeline applies when a hold is shorter than the blend.enter → active → exit as three tracks.
Handover at reststop({ at: 'rest', deadline }) removes the track per item at the first frame its sample equals rest, or at the deadline. The next track was added already and simply becomes the only contributor.turns' handover rule, made available to any pair.
Blend between alternativesmix.blend([a, b, c], by: k) adds three tracks whose weights are the hat functions of k at 0, ½, 1. Continuous, no rebuild, and hinge's quantization goes away for pieces whose channels have rest.hinge's stops mode. Its blend mode is just weight: signal.
Retarget on interruptionfrom: 'current' on a keys track reads the item's merged sample at the track's first frame as stop 0 and lerps from it through the channel's lerp.wod's base-sampling. New to klieg: a regroup could tween from mid-float instead of carrying it away.
the one rule

A weight scales a contribution toward its channel's rest. A lerp moves between two values. Every blend is one or the other, chosen by the channel. A consumer that needs a third arithmetic adds a channel, not a mix option.

Piece state

klieg built three stateful pieces in one week, power, kicks and dwell, and each rediscovered the same three rules: key state by the item object, step once per frame by the gap in now, snap under infinite dt. Those rules are the package's, applied by the mix, and a piece declares only what its state is and how it advances.

const power = piece<PartInfo, PartOffset, PowerState>(0, (t, part, ctx) => {
  const s = ctx.state;
  return s.mode === 'on' ? {} : { gain: s.gain };
}, {
  state: () => ({ mode: 'on', gain: 1, since: 0 }),
  step: (s, dt, part, ctx) => { /* advance the strike, the flare, the warm-up */ },
});

Sign-wide state, which power has, is per-item state on a shared item: the piece's state returns one object from a closure and every part reads it. The mix does not need to know.

Engines

The engine is the implementation behind Mix. The schema above is data plus pure functions, so a mix can be interpreted by more than one thing. One engine ships, and the seam is designed so the second one does not need the first rewritten.

interface Engine {
  readonly name: string;
  /** Which piece forms this engine can run. A track whose piece it cannot run is refused at `add`, by name. */
  readonly runs: ReadonlySet<'fn' | 'keys'>;
  /** Builds the mix. Everything on `Mix` is the engine's to implement. */
  create<I, O>(table: Table<O>, opts: MixOptions<I, O>): Mix<I, O>;
}

export const mixer: Engine;   // the one that ships

mixer runs both forms on the CPU, samples per item on demand, and is the extraction of what klieg does today. What later engines would look like, so the seam is judged against something real and none of them is being built:

  • A baked engine runs keys tracks only and emits Web Animations or CSS keyframes, so a DOM consumer like wod gets compositor-thread playback. It refuses fn pieces at add.
  • A recording engine wraps another engine and captures every sample into keyframes, turning a procedural piece into data for the baked one.
  • A GPU engine writes per-item offsets into a buffer instead of returning them, for a part count where a JS loop per frame is the cost. Same table, same tracks; sample becomes a read from the buffer.

The seam holds only if nothing outside the engine assumes sampling is a function call. Two consequences for the schema: sample takes an out parameter so a buffer-backed engine can fill in place, and keys pieces keep their stops on the object rather than closing over them.

The klieg port

All three klieg systems move in one pass, as chosen. The port is an extraction first and a feature second, and the boundary between the two is where the baselines are checked.

  • Step one reproduces the arithmetic exactly. Timeline.poseAt becomes three tracks whose weight function is min(inW, outW) with the group cap, and EffectFrame.resolve becomes a mix over parts with the same modulo pass and the same stagger call. mergeOffsets and addScaled are the channel tables. The 40 Playwright baselines and every vitest case hold unchanged. Any that moves is a defect in the port, not a baseline to re-bless.
  • Step two turns on what the extraction bought. power, kicks and dwell lose their hand-rolled frame keying. hinge's blend mode becomes weight: signal and its stops mode becomes mix.blend; the old names stay as sugar. A host can add an effect to a running fire and fade it in, which has no equivalent today.
  • Wrappers do not move. turns, roving, intermittent, partition and the Sequence's carry and within stay piece-level and unchanged, except that carry can be deleted once a regroup uses from: 'current'.
  • FrameCtx becomes Ctx with klieg's fields on host. pointer, pointerInWord and dt keep their meanings. Every klieg piece signature changes by one property path, and a codemod does it.
  • klieg gains one runtime dependency, zero-dependency itself, ESM-only, with types.

Decided against

  • A signal graph. Everything as nodes evaluated once per frame. Most general, and every existing piece would be re-expressed as nodes; a misbehaving sign would be read as a graph rather than a list. Signals stay scalars and plug in at two places.
  • Keyframes as the only form. The platform's shape and wod's. It cannot carry a hash-driven flicker or a permutation walk without an escape hatch that is the procedural form under another name. Both forms are first-class instead.
  • Adopting a tweening library. GSAP, anime.js and Motion own a property and write absolute values, so concurrent writers conflict. anime.js v4's additive mode is the closest and still has no rest rule per channel. three's AnimationMixer has the right model and is keyframe-only over object property paths.
  • Item registration. A mix.items(list) call would let the mix step every state eagerly. It puts a second source of truth about the pool in the host. Lazy state keyed by identity, stepped by the gap in now, needs nothing from the host and is the rule klieg already proved.
  • A mix option for the lurch guard. A global "normalize when over 1" would apply to effects that legitimately stack. The cap belongs to the tracks that crossfade, so it is a group.

Tests

  • Channel laws, property-tested per stock channel: join(v, rest) = v, scale(v, 1) = v, scale(v, 0) = rest, lerp(a, b, 0) = a, lerp(a, b, 1) = b.
  • One frame, one answer. A stateful piece sampled 12 times at one now steps once; a second step with the same now is a no-op.
  • Catch-up. An item unsampled for three frames steps by the whole gap on the fourth.
  • Fade continuity. A track stopped mid-pass with a fade produces no frame-to-frame jump larger than its per-frame ramp, on every channel with rest.
  • Retarget continuity. A from: 'current' track added on a moving item has a first sample equal to the item's previous sample.
  • Group cap. Two tracks in a group at weight 1 each produce the same output as one at weight 1.
  • Handover. stop({ at: 'rest' }) removes per item at the first resting frame, and at the deadline for a piece that never rests.
  • Engine refusal. An engine whose runs lacks fn throws at add naming the track.
  • The klieg extraction is judged by klieg's own suites and the Playwright baselines, unchanged.

Open

  • The package name. blits is free on npm. @lightningjs/blits is a live TV app framework with its own animation plugin, so searches for the name land there first.
  • Where klieg's stagger lives. The grammar is generic already; whether StaggerSpec and orderKey move into the package or stay klieg's and are passed in as a function.
  • Color's lerp. A hex channel needs a color space to lerp in. sRGB is what klieg's light channel assumes; OKLCH reads better for a crossfade between hues. One choice, made once, on the stock hex channel.
  • Whether magicsmoke wants this at all. Its fault is one intensity; the case is weakest there and it may stay a consumer only of ease.
