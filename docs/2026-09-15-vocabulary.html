Eighteen roles, twelve verbs, twenty words each

The vocabulary in the schema draft is klieg's, kept because it was there. This sheet puts every role beside twenty alternatives drawn from the fields that already have a word for it, so the right one can be recognized rather than argued for.

For: choosing the names before anything is typed. Answers: what each role is, what other fields call it, and which set holds together. Reads with the schema draft.

Naming open · nothing built · 2026-09-15

Why offset

It is klieg's own word, and it says the one thing that matters about what a piece emits: the value is relative to rest, not absolute. A piece that writes nothing contributes nothing; position rests at 0 and gain at 1; the merge is a fold of relative contributions. That is what lets layers compose without knowing about each other.

It is wrong in two places. Color replaces rather than offsets, and a retargeted keyframe track holds absolute stops. It also covers two things at once: what a piece emits, a partial relative record, and what the mix returns, a resolved absolute one. klieg calls those PartOffset and ResolvedOffset. A rename can split them, and the first term below carries both.

The roles, as relations

How the quantities stand to each other, one line each, before any of them is defined precisely. Read = as "is made of" or "is computed from", and Σ as "the fold of", using whatever rule the channel has.

channel = values + rule
a set of values, and how two of them combine
table = { channel₁ … channelₙ }
the axes one kind of thing can move on
offset ⊂ table
one value on some of those axes; the rest absent
offset = piece(phase, item)
what one effect says about one thing at one instant
phase = ((now − start) · rate) mod period
a track's own clock, normalized to its period
track = piece + clock + weight + target
an effect given a start, a speed, a volume, a set of things
weight = envelope(now)  or  signal(item)
how much of a track is on: a ramp in time, or an outside reading
contribution = weight ⊙ offset
the offset scaled toward rest, per channel
sample = rest ⊕ Σtracks contribution
everything reaching one item this frame, folded, per channel
mix = { track₁ … trackₘ } over one table
what a host holds and steps
handle → track.(start, rate, weight)
the knobs a host may turn between frames
engine(mix, now) = item ↦ sample
whatever computes the fold; one ships

Two of these carry the whole design. contribution = weight ⊙ offset is where every fade, crossfade and blend-between-alternatives happens, because weight is the only thing a mix varies. sample = rest ⊕ Σ contribution is where layering happens, and the rule inside Σ belongs to the channel, so two effects on one axis combine the same way whoever wrote them.

The roles, as algebra

The same relations with their sets and laws made explicit. Nothing here is beyond a product of sets and a fold; the point is that every blend in the package is one of the four channel operations applied under the fold.

channel

A channel c is a value set Vc with four operations:

joinc : Vc × Vc → Vc
restc ∈ Vc  optional
scalec : Vc × [0, 1] → Vc  present iff rest is
lerpc : Vc × Vc × [0, 1] → Vc

Laws: join is associative; join(v, rest) = v; scale(v, 1) = v; scale(v, 0) = rest; lerp(a, b, 0) = a; lerp(a, b, 1) = b. A channel with rest is a monoid. mul is (ℝ, ·, 1); sum is (ℝ, +, 0); max is (ℝ≥0, max, 0); last is (V, second-argument) with no identity.

Strictly, only join is an operation on Vc, in the algebraist’s sense of a map from the set to itself: binary, with rest as its identity. Scale is not: it takes a value and a number from a different set, which makes it an action of [0, 1] on the channel, as scalars act on a vector space, with scale(v, 1) = v as its unit law. Lerp is a family of binary operations indexed by u; on a channel that adds it is the convex combination (1 − u)a + ub and not primitive at all, and it is primitive only where there is no addition to build it from, as for color. Fold, below, is join iterated. A channel is therefore an algebra: a set carrying its operations.

table

A finite indexed family of channels, T = {c1, …, cn}. It defines two spaces:

ΔT = ∏c (Vc ∪ {⊥})  partial: any channel may be absent
ΣT = ∏c Vc  total: every channel present

Δ is what pieces write; Σ is what a host reads. Both are products, so every operation on a table is the channel's operation applied coordinate-wise, with ⊥ treated as "contributes nothing" (it is the unit of join on Δ).

item

An element i of an arbitrary set I. The package never looks inside it; identity is all it uses, for state. A system with no item dimension has I = {∗}.

offset

One element δ ∈ ΔT: the return value of one call to one piece for one item at one instant.

δ = p(t, i, ctx)

Two offsets on the same item compose by joinc per channel. The resolved value a host reads is an element of ΣT, not ΔT; klieg's ResolvedOffset lives there, and the sheet's starred sample is a name for it.

piece

A period dp ∈ ℝ≥0 and a function of normalized time:

p : [0, 1] × I × Ctx → ΔT

Pure in its arguments. A stateful piece carries a state set S with an initial state per item and a step function S × ℝ → S; the mix threads si through ctx, so p stays a function of what it is given. A wrapper is a function Piece → Piece.

signal

σ : I × Ctx → [0, 1]

The same shape as a piece with one channel on [0, 1] and no period. Combinators are pointwise: peak = max, gate = step function, ease = a stateful σ.

track

A tuple k = (p, s, r, w, on): a piece, a start time, a rate, a weight function, and a target predicate I → {0, 1}. Its own clock and its contribution on an item at time τ:

elapsedk(τ) = (τ − s) · r
t = (elapsed mod dp) / dp
wk : ℝ → [0, 1]  an envelope in τ, or σ(i, ctx)
contribk(i, τ) = wk(τ) ⊙ p(t, i, ctx)   where w ⊙ δ = (scalec(δc, w))c

On a channel with no rest, ⊙ is a gate: δc if w > ε, else ⊥. Two tracks of one piece are two tuples; they share p and nothing else.

mix

A finite set of tracks M over one table, and the fold that resolves them:

sampleM(i, τ) = ⨁c  joinc* { contribk(i, τ)c : k ∈ M, onk(i) }   ∈ ΣT

join* folds from restc, so an item nothing reaches samples to rest. Associativity is what makes the fold order-free; last is the one channel where order matters, and it is by declaration. A group G ⊆ M with a cap rescales its weights by 1 / max(1, Σk∈G wk) before ⊙.

The four blends, in these terms: fade is wk a ramp in τ; alternatives are wk = hatk(σ) with Σk hatk = 1; handover removes k from M at the first τ where p(t, i, ctx) = rest; retarget replaces stop 0 of a keyframe piece with sampleM∖{k}(i, s) and moves by lerpc.

handle

A reference to one k ∈ M with write access to s, r and w, and the event k ∉ M. It adds nothing to the algebra; it is how a host mutates a tuple between frames.

engine

An implementation of sample:

E : (T, M, τ) → (I → ΣT)

Two engines are interchangeable exactly when they agree on every (T, M, τ) whose pieces both can run. That equation is the port's test: Emixer must equal klieg's three merge functions on every input klieg's suites already exercise.

Read across, the whole package is: pieces produce elements of Δ; tracks weight them with ⊙; a mix folds them with join into Σ; an engine is any function that computes that fold. The channel table is the only place arithmetic is defined, so a consumer that needs a new blend adds a channel with a new (join, rest, scale, lerp), never a new rule in the mix.

Six consistent sets

Six fields each give a complete vocabulary for the whole pipeline. The learning column lands on the same three roles the geometry does, with the same split: feature for one coordinate, feature space for all of them, feature vector for one point; and it gives residual, ensemble and epoch, each exact. The physics column is the one that says what the mix is: forces from independent sources superposing on a body into one resultant, with a field assigning one to every point. Its cost is that forces add and half the channels multiply, and that force is a flag and a physics-engine word in the same codebases. Any one column reads as a system; mixing columns reads as arbitrary, with one exception: the algebra column is strong exactly where the arithmetic lives (domain, axis, term, curve) and strained where the host lives, so a set that is mathematical on the left of the fold and plain on the right matches what each part is.

Terms

Each role, what it is, and twenty words for it grouped by where they come from. Synonyms of the current word were left out on purpose; these are the words other fields use for the same job.

Offset

was offset

What one call to a piece returns: a record with one slot per channel of the table.

  • The piece fills only the slots it drives and leaves the others empty. Flicker fills gain; slam fills position and scale; hue fills color.
  • Which slots come back is the piece’s own decision, and it may differ from call to call.
  • A filled slot is a change from the channel’s rest: gain: 0.1 means multiply by 0.1, not set to 0.1.
  • An empty slot means no contribution. The merge skips it.

Channel

was channel

One slot in an offset: one name, one rule for combining two values written into it.

  • Gain is a channel whose values multiply. Position is a channel whose triples add.
  • The rule belongs to the channel, so what happens when two pieces write the same slot is settled once, not per piece.
  • One name and one rule whatever the shape of the values: gain is a single number, position is three under one rule.

Table

was table

The full list of channels one kind of thing can be moved on, each with its rule.

  • klieg has three: a pose table for a letter, a part table for a tube run or a flake, a lighting table for the whole frame.
  • A piece writes into one table. A mix runs over one table.
  • It is a closed list: a piece cannot write a channel the table does not have.

Handle

was handle

The remote for one track: what add gives back so you can point at that track later.

  • You add a flicker. Three seconds on, the cursor leaves and you want that flicker to fade out, not the other twelve tracks. The handle is how you say which one.
  • Through it you can set the track’s weight and rate, seek its clock, and stop it. Each lands on the next frame.
  • Its done promise resolves when the track has left the mix by any route, so a host can await an effect finishing.
  • The same idea as the id setTimeout returns, or the object element.animate() returns, or klieg’s own FireHandle.

Sample

was ResolvedOffset

What one item looks like at one frame, after every track has been merged.

  • A frame is a moment: one tick of the clock across the whole mix. A sample is one cell of it: one item at that tick. A frame with 24 tube runs holds 24 samples.

  • The host reads it and writes it to the screen: a mesh’s position, a wedge’s opacity, a gain node’s level.
  • klieg’s name for it, ResolvedOffset, says how it is made rather than what it is.

Phase

was tfixed

Where a track is within its period, from 0 to 1, wrapping.

Group

was group

A label shared by tracks that are alternatives in time.

  • klieg’s enter, active and exit are one group.
  • Within a group the weights are capped to sum to at most 1, so a crossfade is always a blend of the two and never a pile-up.
  • Tracks meant to stack stay out of groups.

On domain for the channel set

Revised. The objection below measured the word against the piece, whose output is the offset space. The table defines join, scale and lerp, and those act on the value space, so for them it is the domain in the strict sense, and so is the mix's fold. The klieg collision is not a constraint: Mike said on 2026-09-15 that klieg changes if it has to, provided blits produces something good, so the gradient's domain renames if this word is taken. domain now ranks with rig: the one for a mathematical register, the other for the puppet.

The original note, kept for the record. It works as English and has two collisions, one of them in klieg.

  • Math puts it at the wrong end. A clip maps time and a target to an offset. The offset space is the codomain; the domain is time. d3 uses the words the same way: domain is input, range is output. Anyone who knows either reads "the pose domain" as time.
  • klieg already uses it. The gradient's letter domain is the span a color ramp runs over. A second, unrelated domain in the same package's types is a collision a reader hits once and distrusts forever.

What it gets right is the feel: "the pose domain" says the area where pose values live, which is better than table, which says data structure. Two words keep that feel without the collisions. space is the math word for the output side: "pose space", "part space", "presence space" all read as the set of values a thing can take. rig says it from the animation side: the set of controls a thing is driven through.

What I would take

recommendation

Mathematical where the arithmetic lives, plain where the host lives. domain for the channel set, axis for one channel, term for what a piece returns, curve for the piece itself; with them, origin for rest and coefficient for weight. On the host side the DAW words stay: track, mix, signal, handle, engine, and item for the driven thing until a better one turns up. The page opens on this set.

In one sentence: a curve returns a term; the coefficient scales it toward the origin; the mix folds the terms along each axis of the domain. Every word in it is doing exact work.
