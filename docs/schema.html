blits · design

An effects schema, and the API around it

A small runtime package for concurrent effects. Each effect runs on its own clock with its own state and weight, and a mix folds them into one value per subject per frame by rules that belong to the channel, not the effect.

For: whoever builds blits, and whoever ports klieg, wod, sherpa or magicsmoke onto it. Answers: what the vocabulary is, what an author writes, what a host calls, and where a second engine would plug in. The package implements this page; where the two differ, the code in src/ is the one that runs.

Built · v0.1.0 · design 2026-09-15, package 2026-09-28

In one picture

A host syncs the mix once a frame. For each subject it wants drawn, the mix samples every voice that reaches that subject, scales each delta toward its channel's rest by the voice's current weight, joins them channel by channel, and hands back one pose. The host writes that pose wherever it goes: a three.js mesh, an SVG wedge, a CSS transform, an audio gain.

Everything klieg does today fits this picture, in three copies with three channel sets. wod's transition voices are the same picture with one subject type and a retargeting tween. sherpa's seam is two voices. magicsmoke's fault is one voice whose weight is a signal.

Vocabulary

Every other name in the package is built from these.

Delta
A partial record of channel values. A patch writes only the channels it drives; an absent channel means no influence.
Channel
One field of a delta, with its own arithmetic: how two influences join, what rest is if there is one, how to scale toward rest, how to lerp.
Rig
The channel set for one kind of delta. klieg's pose, klieg's part, wod's presence are each a rig.
Subject
What is being driven: a letter, a part, a wedge, a page, or a unit value for a system with no subject dimension such as klieg's lighting.
Patch
A pure function of phase and a subject that returns a delta. Optionally stateful. This is klieg's word and it keeps it.
Voice
A patch plus its own playback: start, rate, loop, weight envelope, target, and blend options. The unit a host cues and fades.
Mix
The set of live voices over one rig, synced once a frame and sampled per subject. What a host holds.
Signal
A 0..1 scalar resolved per subject per frame from something outside the clock: the cursor, a hover value, another voice's state.
Handle
What cue returns: the live controls on one voice, and its completion.
Engine
The implementation behind a mix. One ships. The seam is the mix's own interface.
Pose
What one subject looks like at one frame, once every voice has been folded in. Where a delta is partial, a pose is complete: every channel of the rig is filled. This is what a host writes.
Influence
What one voice does to one subject in one frame, once its weight is applied. Not a share of the whole: two voices each contributing gain: 0.1 leave the subject at 0.01.
Period
How long one pass of a patch lasts, in milliseconds. 0 means aperiodic.
Phase
Where a voice is within its period, 0 to 1, wrapping. The first thing a patch is handed, and what stagger spreads per subject.
Setting
What a patch may read and did not compute, for one subject this frame: the clock and dt the whole frame shares, the elapsed, pass and weight particular to the voice, its state, and whatever the host added.
System
One complete area of driven behavior: a rig, the subject type it drives, and the mix over them. klieg's motion, effects and lighting are three systems in one host. Two systems never share a mix, so a voice belongs to exactly one.
Source
Whatever decided a voice should exist: a score, a handler on an event, a chain handing over. There is no source type and nothing to implement — a source calls cue and gets a handle. The word is here so the vocabulary can name the seam it does not own.
Score
The source that holds a host's whole plan: what plays, over what, and when. It supplies the two things blits takes as given, the timing and the cast of subjects. klieg's is spread across handlers and a Timeline; another host's may be a document or a route table. It is coming inside, as a plan of voices placed on the mix clock that knows when each plays and never what it contributes; see Open.

Channels

The arithmetic of blending is a property of the operand type, so it lives on the channel and nowhere else. Every merge, fade, crossfade, and retarget in the package is one of these four operations.

interface Channel<V> {
  /** Identity. Absent means the channel has none: `color` replaces rather than contributes. */
  rest?: V;
  /** Fold two influences into one. */
  join(a: V, b: V): V;
  /** Fade toward `rest` by weight 0..1. Required when `rest` is set; absent otherwise. */
  scale?(v: V, w: number): V;
  /** Interpolate, for retargeting and for blending alternatives. */
  lerp(a: V, b: V, u: number): V;
}

type Rig<O> = { readonly [K in keyof O]-?: Channel<NonNullable<O[K]>> };

Stock channels cover every case the four repos hold today:

channelrestjoinscalelerpused by
sum()0a + bv · wlinearposition axes, rotation, crawl, yaw, pitch, offset
mul()1a · b1 + (v − 1) · wlineargain, scale, opacity, hold
max()0max(a, b)v · wlineardark, aperture
last()noneb—caller'scolor, offsetAngle
vec(n, ch)per axisper axisper axisper axisVec3 position, premultiplied light

A channel with no rest cannot fade. The mix handles that in one way: below a weight threshold the influence is dropped, above it the value passes through whole. That is the rule hinge's blend mode already applies to color, and it is stated here once so no consumer rediscovers it. The threshold is a band, not an edge — it drops at off and passes at on, and between the two it holds whatever it last did. One edge chatters: a weight resting on it is carried back and forth by frame noise, and every crossing drops or restores the whole influence. Retargeting is the way a rest-less channel does move smoothly, since a lerp from a sampled value needs no identity.

The stock set is not the limit: a consumer that needs arithmetic it lacks writes its own Channel, and nothing in the mix knows the difference. sherpa's transform is one, composed by the host from whatever it puts in a matrix.

A rig is plain data, so a consumer declares one in a line and the mix is typed by it:

const PART = rig<PartOffset>({
  gain: mul(), scale: mul(), dark: max(), crawl: sum(),
  position: vec(3, sum()), rotation: vec(3, sum()),
  light: vec(3, sum()), color: hex(),
});

Patches

A patch is what an author writes. It is klieg's EffectPiece with three additions: the setting carries absolute time as well as normalized, a patch may declare state, and a patch declares which channels it contributes to.

interface Patch<I, O, S = void> {
  /** Which authoring form built it. An engine declares which forms it runs. */
  readonly form: 'fn' | 'keys';
  /** Milliseconds one pass lasts. 0 is aperiodic: one pass that never ends, so `phase` and `pass` stay 0,
     `loop` is ignored, and the patch reads `setting.elapsed` instead. */
  period: number;
  /** The channels this patch contributes to. Every key `at` sets, and no others. */
  readonly writes: readonly (keyof O)[];
  /** `phase` is 0..1 across one period, wrapping. */
  at(phase: number, subject: I, setting: Setting<S>): Partial<O>;

  /** Per-subject state, created on the first frame this patch sees a subject. */
  state?(subject: I): S;
  /** Advances state once per subject per sampled frame, before that frame's first `at`, by the whole gap
     since that subject last advanced. `dt` is Infinity under reduced motion. */
  step?(state: S, dt: number, subject: I, setting: Setting<S>): void;

  /** Present when the patch was authored as keyframes, so an engine that reads data can. */
  readonly keys?: readonly Keyframe<O>[];
}

interface Setting<S = void> {
  /** The mix clock at this frame. Identical for every sample in the frame. */
  now: number;
  /** The gap this subject is catching up by: milliseconds since it last advanced, which is the gap since
     the previous sync only for a subject sampled every frame. Infinity under reduced motion: snap, never
     integrate. */
  dt: number;
  /** Milliseconds this voice has been playing, rate applied. What lets a patch see across passes. */
  elapsed: number;
  /** Which pass this is, 0 first. */
  pass: number;
  /** This voice's weight for this subject this frame, after its fade envelope, its signal and its share of any group:
     the same number the mix is about to scale by. */
  weight: number;
  /** This subject's state, when the patch declares one. */
  state: S;
  /** Anything the host adds for its own patches: klieg's pointer and pointerInWord go here. */
  host: unknown;
}

Two authoring forms build a patch. Both return the same interface, so a voice cannot tell them apart.

formsignaturewhat it is
fnpatch(period, at, { writes, state?, step? })Procedural. Flicker, roving, a hash walk, a starter strike. Only a JS engine can run one.
keyskeys(period, stops, { ease?, easeBy?, delayBy? })Declarative stops, klieg's transition sugar and wod's keyframes. Data preserved on patch.keys for an engine that reads data instead of calling functions.

writes is the patch's half of the contract the rest of the package already states: a channel rig declares what a consumer has, an engine declares its runs set, and both are checked at cue. Without it the only way to learn what a patch touches is to call it, per subject, per frame. With it the mix refuses a patch contributing a channel the rig lacks, resolves each voice's channels once at cue instead of walking the whole rig per sample, and can answer what a voice affects without sampling it. A keys patch derives it from its stops.

Two small names the page leans on: Easing is a (u: number) => number on 0..1, with the stock curves klieg already ships, and Keyframe<O> is one stop, { at: number; delta: Partial<O>; ease?: Easing }, kept on patch.keys so an engine can read what a keys patch is made of. mixHex is the hex channel's lerp, shipped in sRGB; the color space is open below.

Wrappers stay wrappers. klieg's turns, roving, intermittent, hinge and partition take a patch and return a patch, and none of them changes except to pass writes through — a wrapper reshapes one influence and never adds a channel to it. Composition at the patch level is for reshaping one influence; composition at the mix level is for running several. The two do not merge.

Voices

A voice is a patch given a clock and a volume knob. This is the unit that answers "independent state and timeframe": two voices of the same patch are two clocks, two states, two weights.

interface VoiceSpec<I, O> {
  patch: Patch<I, O, any>;
  /** Which subjects this voice reaches. Default: all of them. The predicate is fixed at `cue`; it runs per
     subject the first time the mix sees that subject, and the answer is kept for as long as the state is. */
  target?: (subject: I) => boolean;

  // clock
  /** Mix-clock ms the voice starts. Default: the next sync. */
  start?: number;
  /** Playback rate. 1 is real time; 0 freezes. */
  rate?: number;
  /** true loops for good, false plays one pass, n plays n passes. A finite loop leaves when its passes are done — over fade.out where one is set, at once where none is. */
  loop?: boolean | number;
  /** Per-subject delay in ms. klieg's stagger grammar stays klieg's and passes in the one thing
     the mix needs: how long this subject waits. */
  stagger?: (subject: I) => number;

  // weight
  /** Steady weight, or a signal read per subject per frame. Default 1. */
  weight?: number | Signal<I>;
  /** Ramp in and out, ms. Out applies on `fade()` and when a finite loop ends. */
  fade?: { in?: number; out?: number; ease?: Easing };
  /** Voices sharing a group are alternatives: the mix folds them into one influence through each
     channel's `lerp` before anything else sees them. A crossfade between two behaviors, not what
     klieg's phases are: those layer. */
  group?: string;

  // blend
  /** A `keys` patch whose first stop reads "wherever this subject is now", lerped over the pass. Read from
     the pose of the frame before this voice first contributes, so it never reads itself. With no
     such frame on record it is this frame's pose with every other voice folded in. */
  from?: 'current';
}

interface Handle {
  readonly id: number;
  readonly state: 'pending' | 'live' | 'fading' | 'done';
  /** Live. Writes land on the next sync. */
  weight: number;
  rate: number;
  /** Moves this voice's clock, forward or back. Phase is computed from the reading rather than accumulated
     into, so nothing has to unwind: state is left where it is and is never run forward to meet the new
     position. Mix time is not addressable this way, and nothing outside this voice moves. */
  seek(elapsed: number): void;
  /** Ramps out over `fade.out` unless given a fade here; `at: 'rest'` waits per subject for a resting pose first. */
  fade(opts?: { over?: number; at?: 'rest'; deadline?: number }): void;
  /** Resolves when the voice has been removed from the mix, however that happened. */
  readonly done: Promise<void>;
}

Weights are the only knob the mix owns. Fade, crossfade, handover, alternatives, and hinge's continuous mode are all weights over time; the section on blending shows each one as such. A patch never sees a weight applied to its output, it only sees the number in setting.weight if it cares.

Mix

What a host holds. The methods are few because the voices carry the options.

function mix<I, O>(rig: Rig<O>, opts?: MixOptions): Mix<I, O>;

interface MixOptions {
  engine?: Engine;                // default: mixer
  /** Reduced motion: fades and warm-ups snap, `dt` reads Infinity. Read once at creation, or a signal. */
  reduce?: boolean | (() => boolean);
  /** Merged into every `setting.host`. */
  host?: unknown;
  /** The band a rest-less channel's influence switches across. Default 0.4 / 0.6, a placeholder. */
  band?: { on: number; off: number };
}

interface Mix<I, O> {
  /** Cues a voice. Throws when the engine cannot run the patch's form, or the rig lacks a channel it `writes`. */
  cue(spec: VoiceSpec<I, O>): Handle;
  /** N voices whose weights split one signal, k in 0..1, cued into one group so they fold as
     alternatives. Two patches crossfade; more make stops. */
  blend(patches: readonly Patch<I, O>[], by: Signal<I>, spec?: Omit<VoiceSpec<I, O>, 'patch' | 'weight'>): Handle[];

  /** The host reports the clock, once a frame. Nothing advances at the call: it publishes the reading, and
     each subject catches up by the whole gap the first time it is sampled afterward. The same `now` twice
     changes nothing, and the reading only ever goes forward. */
  sync(now: number): void;
  /** The merged pose for one subject at the synced frame. `out` is written in place when given. */
  sample(subject: I, out?: O): O;
  /** Every channel at rest for this subject this frame, so a host can skip the write. */
  atRest(subject: I): boolean;

  /** Anything still contributing, fading, or pending. A host stops its loop when this is false. `cue` and
     `blend` make it true again at once; the mix never calls back into the host, so restarting the loop is
     the caller's to do on the same path that cued. */
  readonly live: boolean;
  /** Fades every voice out: over `over` when given, over each voice's own `fade.out` otherwise. */
  clear(opts?: { over?: number }): void;
  /** Forgets per-subject state. Call when a subject is retired, or let the WeakMap do it. */
  drop(subject: I): void;
}

Subjects are not registered. State lives in a WeakMap keyed by the subject object, created on first sample and stepped by the gap in now since that subject was last stepped. That is the rule klieg's dwell arrived at, and it means a part a wrapper leaves unasked for a while catches up rather than resuming where it paused.

Signals

A signal is a 0..1 scalar resolved per subject per frame. It is the package's one input type from outside the clock, and it plugs in at exactly two places: a voice's weight, and blend's selector.

type Signal<I> = (subject: I, setting: Setting) => number;

// stock combinators; klieg's own `near`, `dwell`, `level` are consumers' signals built on these
function peak<I>(...signals: Signal<I>[]): Signal<I>;          // max
function slew<I>(of: Signal<I>, { riseMs, fallMs }): Signal<I>;  // stateful: rate-limited follow toward its input
function level<I>(initial?: number): Signal<I> & { set(v: number): void };  // host-written
function gate<I>(of: Signal<I>, band: { on: number; off: number }): Signal<I>;  // stateful: holds inside the band
function gate<I>(of: Signal<I>, at: number): Signal<I>;          // sugar for on = off = at

A stateful signal keeps state the same way a stateful patch does: per subject, keyed by identity, stepped by the gap in now. The state belongs to the signal instance, not to the voice reading it, so two voices handed the same slew share its per-subject value and two slews of the same shape do not. slew is klieg's dwell with the cursor factored out; gate keeps one bit, which way it last switched.

slew is the package's one decay primitive: a value that follows its input at a rate limit, no faster than riseMs per unit climbing or fallMs draining. It is not Easing, which is a curve over a known duration, and it is not called ease for that reason — fade.ease and keys({ ease }) already mean the curve. A decay tail is a slew to 0 with no rise; a fade is a slew on a weight; klieg's kicks is a slew to 0 that peak pokes back up. Nothing else in the package stores a value in order to lag it. gate is the other half of that pair and not a substitute for it: a slew sets how fast a value may move, a band sets whether it may move at all. A slew cannot quiet a gate, because a rate limit delays a crossing without deciding it, and an input resting on the threshold drags the slewed value onto the threshold with it.

Time

  • The mix is pull-based on a host clock. The host owns the frame loop and calls sync(now) with milliseconds on any monotonic clock it likes. klieg passes its Clock.now(); wod passes performance.now(); a test passes integers.
  • Everything in a frame reads one now. A second sync with the same value is a no-op, and every sample between syncs answers from the same frame. This is what makes state advance once however many probes a wrapper makes.
  • A voice's clock is (now − start) · rate. That reading is setting.elapsed, and its position within the period, (elapsed mod period) / period, is the phase the patch is handed first. Both reach the patch. A rate change rebases so elapsed is continuous.
  • dt is derived, never supplied. The gap between this sync and the last, per subject, and Infinity under reduced motion. A patch that integrates guards against that with a snap, as klieg's already do.
  • Calls land on the next sync. A host writes handle.weight or calls fade on its own clock; the mix applies it at the first now that sees it. Nothing changes mid-frame.

Blending

The four behaviors asked for, each as the weight or lerp it reduces to. Nothing here is a mechanism of its own.

behaviorhowwhat it replaces
Fade in and outfade: { in, out } ramps the voice's weight; each channel's scale takes it toward rest.klieg's Timeline.weight, the blendMs ramps, and carry.
Crossfade at a phase seamTwo voices in one group, one fading out as the other fades in. The group folds them by the channel's lerp at their weight ratio, which on sum is the lurch guard klieg's timeline applies when a hold is shorter than the blend, and on every other channel is the crossfade that guard was standing in for.enter → active → exit as three voices.
Handover at restfade({ at: 'rest', deadline }) removes the voice per subject at the first frame its pose equals rest, or at the deadline. The next voice was cued already and simply becomes the only contributor.turns' handover rule, made available to any pair.
Blend between alternativesmix.blend([a, b, c], by: k) cues three voices whose weights are the hat functions of k at 0, ½, 1. Continuous, no rebuild, and hinge's quantization goes away for patches whose channels have rest.hinge's stops mode. Its blend mode is just weight: signal.
Retarget on interruptionfrom: 'current' on a keys voice takes stop 0 from the subject's pose in the frame before it first contributes — every other voice folded in, itself excluded — and lerps from there through the channel's lerp.wod's base-sampling. New to klieg: a regroup could tween from mid-float instead of carrying it away.

A group is folded by lerp, not by scaling and joining. Voices sharing a group are alternatives in time, so the mix combines them into one influence first: each member weighted by its share of the group's summed weight, through the channel's own lerp, in cue order. That one influence then contributes at weight min(1, Σw) and is scaled toward rest like any other. On a sum channel this is exactly w₁a + w₂b, the arithmetic klieg's timeline already runs, so the cap it was written as is a special case of the fold rather than a rule of its own. On mul, max and last it is the difference between an alternative and a pile-up: two voices halfway through a handover, both holding a gain of 0.06, fold to 0.06 — which is what one alternative means — where scaling and joining reads 0.28, the product of two half-scaled copies. A grouped voice may write only channels that have a lerp, which every stock channel does. Cue order is visible only to a lerp that is not linear, such as a hue taking the short way round.

the one rule

A weight scales an influence toward its channel's rest. A lerp moves between two values. Every blend is one or the other, chosen by the channel. A consumer that needs a third arithmetic adds a channel, not a mix option.

Patch state

klieg built three stateful patches in one week, power, kicks and dwell, and each rediscovered the same three rules: key state by the subject object, step once per frame by the gap in now, snap under infinite dt. Those rules are the package's, applied by the mix, and a patch declares only what its state is and how it advances.

const power = patch<PartInfo, PartOffset, PowerState>(0, (phase, part, setting) => {
  const s = setting.state;
  return s.mode === 'on' ? {} : { gain: s.gain };
}, {
  state: () => ({ mode: 'on', gain: 1, since: 0 }),
  step: (s, dt, part, setting) => { /* advance the strike, the flare, the warm-up */ },
});

Sign-wide state, which power has, is per-subject state on a shared subject: the patch's state returns one object from a closure and every part reads it. The mix does not need to know.

Engines

The engine is the implementation behind Mix. The schema above is data plus pure functions, so a mix can be interpreted by more than one thing. One engine ships, and the seam is designed so the second one does not need the first rewritten.

interface Engine {
  readonly name: string;
  /** Which patch forms this engine can run. A voice whose patch it cannot run is refused at `cue`, by name. */
  readonly runs: ReadonlySet<'fn' | 'keys'>;
  /** Builds the mix. Everything on `Mix` is the engine's to implement. */
  create<I, O>(rig: Rig<O>, opts: MixOptions): Mix<I, O>;
}

export const mixer: Engine;   // the one that ships

mixer runs both forms on the CPU, samples per subject on demand, and is the extraction of what klieg does today. It folds each influence into the subject's accumulator as it samples, rather than collecting every layer and merging at the end as klieg's EffectFrame does: weights are scalars that no pose depends on, so they resolve for the subject first, and a group folds to one influence before that influence is joined. That order is what would let a later revision hand patches one scratch object to write into instead of returning a fresh partial per patch per subject per frame, which writes makes safe to hand out without clearing. What later engines would look like, so the seam is judged against something real and none of them is being built:

  • A baked engine runs keys voices only and emits Web Animations or CSS keyframes, so a DOM consumer like wod gets compositor-thread playback. It refuses fn patches at cue.
  • A recording engine wraps another engine and captures every pose into keyframes, turning a procedural patch into data for the baked one.
  • A GPU engine writes per-subject deltas into a buffer instead of returning them, for a part count where a JS loop per frame is the cost. Same rig, same voices; sample becomes a read from the buffer.

The seam holds only if nothing outside the engine assumes sampling is a function call. Two consequences for the schema: sample takes an out parameter so a buffer-backed engine can fill in place, and keys patches keep their stops on the object rather than closing over them.

The klieg port

All three klieg systems move in one pass, as chosen. The port is an extraction first and a feature second, and the boundary between the two is where the baselines are checked.

  • Step one reproduced the arithmetic exactly, and is done. Timeline.poseAt is a voice per layer of each phase, weighted min(inW, outW); EffectFrame.resolve is a mix over parts with the same modulo pass and the same stagger call; the sign’s environment is a mix with one subject. mergeOffsets, addScaled, accumulate, scaleOffset and mergeEnv are all the channel rigs now. klieg’s vitest suites and the Playwright baselines hold unchanged.
  • Stagger stayed klieg's, and the two are not the same operation. A voice's stagger delays a subject by milliseconds; klieg's warps the pass into (t − start) / span and clamps, so a part reaches the end of its pass with the word rather than after it. The port computes it in the patch, from setting.elapsed, and orderKey stays klieg's with it.
  • A phase is a layer, not an alternative. The three phases cue as separate voices, not as one group: a group folds through lerp, which is identically scaling and joining on sum but not on mul — and scale and opacity are mul channels that two phases both write inside a blend window. klieg’s own guard against three phases overlapping at once, scaling every weight by 1/Σw when the sum runs past 1, stays klieg’s for the same reason: it is a property of its phase table, not of the fold. A group is still the right shape for alternatives that replace one another, which is what mix.blend cues.
  • Step two turns on what the extraction bought. power, kicks and dwell lose their hand-rolled frame keying, and slew takes the decay math with it: dwell's toward and kicks' drain are one function, leaving kicks its falloff and its event queue. power keeps its state machine, which is not a decay. hinge's blend mode becomes weight: signal and its stops mode becomes mix.blend; the old names stay as sugar. A host can cue an effect to a running fire and fade it in, which has no equivalent today.
  • Wrappers do not move. turns, roving, intermittent, partition and the Sequence's carry and within stay patch-level and unchanged, except that carry can be deleted once a regroup uses from: 'current'.
  • FrameCtx becomes Setting with klieg's fields on host. pointer, pointerInWord and dt keep their meanings. Every klieg patch signature changes by one property path, and a codemod does it.
  • klieg gains one runtime dependency, zero-dependency itself, ESM-only, with types.

Decided against

  • A signal graph. Everything as nodes evaluated once per frame. Most general, and every existing patch would be re-expressed as nodes; a misbehaving sign would be read as a graph rather than a list. Signals stay scalars and plug in at two places.
  • Keyframes as the only form. The platform's shape and wod's. It cannot carry a hash-driven flicker or a permutation walk without an escape hatch that is the procedural form under another name. Both forms are first-class instead.
  • Adopting a tweening library. GSAP, anime.js and Motion own a property and write absolute values, so concurrent writers conflict. anime.js v4's additive mode is the closest and still has no rest rule per channel. three's AnimationMixer has the right model and is keyframe-only over object property paths.
  • Subject registration. A mix.subjects(list) call would let the mix step every state eagerly. It puts a second source of truth about the pool in the host. Lazy state keyed by identity, stepped by the gap in now, needs nothing from the host and is the rule klieg already proved.
  • A slew in place of the band. Smoothing a gate's input instead of giving it two edges. It delays the crossing without deciding it, so an input that rests on the threshold chatters anyway, and the rate needed to help at all costs visible lag.
  • Normalizing a group's weights per channel. The other way to make a crossfade hold its value on mul: keep the scale-and-join fold and pick a per-channel divisor. It costs the property the mixer's fold order rests on — that weights are scalars resolved for the subject before any channel is touched — and it has no answer for last, which has no arithmetic to normalize. The lerp fold gets the same result from the rule the package already has.
  • A mix option for the lurch guard. A global "normalize when over 1" would apply to effects that legitimately stack. The cap belongs to the voices that crossfade, so it is a group.

Tests

These are the package's suite, in test/. Everything below the klieg extraction is written and green.

  • Channel laws, property-tested per stock channel over a deterministic sample: join(v, rest) = v, scale(v, 1) = v, scale(v, 0) = rest, lerp(a, b, 0) = a, lerp(a, b, 1) = b. Each holds on the channel's own domain — max's rest is an identity for values at or above it, which is what dark and aperture are.
  • One frame, one answer. A stateful patch sampled 12 times at one now steps once; a second sync with the same now is a no-op.
  • Catch-up. A subject unsampled for three frames steps by the whole gap on the fourth.
  • Fade continuity. A voice stopped mid-pass with a fade produces no frame-to-frame jump larger than its per-frame ramp, on every channel with rest.
  • Retarget continuity. A from: 'current' voice cued on a moving subject has a first sample equal to the subject's previous sample.
  • Band quiet. A signal held inside a gate's band for a whole pass produces no switch, whatever it does inside it. Same for a rest-less channel's influence under a weight that wanders between off and on.
  • Group fold. Two voices in a group driving the same value produce that value, on every stock channel — the invariant the old cap met on sum alone. At unequal values they produce the channel's lerp at their weight ratio, which on sum is the number scaling and joining already gives and is what keeps klieg's baselines green. A group whose weights sum below 1 scales the folded value toward rest by the sum; above 1 it caps at 1.
  • Handover. fade({ at: 'rest' }) removes per subject at the first resting frame, and at the deadline for a patch that never rests.
  • Declared writes. A patch's at sets no key outside its writes, on every subject and every pass. A voice whose patch writes a channel the rig lacks throws at cue naming both.
  • Engine refusal. An engine whose runs lacks fn throws at cue naming the voice.
  • The klieg extraction is judged by klieg's own suites and the Playwright baselines, unchanged.

Open

  • How the score comes inside. Decided 2026-09-29: it comes inside, provided it depends on no implementation. It places voices from any number of unrelated sources and knows when each plays, for how long, at what weight and relative to which other voice — never what a voice contributes. Meaning stays in the patches and the rig’s channels, which is the line the fold already draws. Scores compose dynamically, favored where it holds up: each source keeps its own, the mix reads every score it holds the way a DAW plays every track, and a source joins or leaves without touching anyone else’s plan. One shared score is the case with one source. Until now a score was a word for a seam blits does not own: blits takes timing as given and reads only what has been cued, so it sees no further ahead than its pending voices, and a host that knows what is coming does the arithmetic itself — to be faded in by T, it cues with start: T − fade.in. A score inside blits would be data: voices placed on the mix clock, at a time or relative to one another (after, with, before, fully in by), which the mix plays by reading it at now, the way a DAW plays its arrangement at the playhead. The fold does not change, since the mix already folds any number of voices at a time. What changes is that the whole plan can be read at any time: mix.peek(subject, at) for what is coming, and, because the plan is kept rather than used up, a way back that the mix’s lack of history rules out today. A chain, voices that hand over in order, becomes one arrangement a score can hold rather than an object of its own. Reading at another time is where state gets in the way, and the approach is for the mix to own all of it. Signals declare state the way patches do (state and step) instead of keeping it in a closure — today slew and gate write back on every call, so a naive peek would move the live signal. A read ahead copies the state (structuredClone by default, a clone on the patch or signal where the state is not plain data), steps it to at, samples, and throws the copy away. It takes one step per stretch between the events the score already knows — a voice starting, a fade ending, a loop running out — since any of them can change what a stateful signal follows, and each step covers its whole stretch, however long. That leans on a contract the whole-gap rule already assumes and nothing states: one step across a stretch is as good as any number of steps across it. Steps need not be uniform or frame by frame. An answer is exact across known events. An input the clock drives continuously, such as a slew following a sine, is exact only to the length of the step, which is an error of stepping rather than of knowledge: a finer split, or a patch or signal that gives its own closed form for a long gap, removes it. An input from outside the clock — a level the host sets, a pointer — has no known future, so it is held where it is and the answer says it is a projection. Reading back is the same copy replayed forward from a kept checkpoint, and waits on a bound for how much history the mix keeps. The proposed shape of a placement, unbuilt: a voice has four edges on the mix clock — start (fade-in begins), in (full weight), out (fade-out begins) and end (gone) — and a cue pins at most one edge on each side, start or in and out or end, to a time or to another voice’s edge with an offset: pin: { in: 12_400 } is fully in by 12.4 s, pin: { start: { after: 'intro' } } starts once intro is gone. A voice is named by a key its source gives it, a label blits never reads. Keys are namespaced by score: a bare key names a voice in the same score, and { score, key } one in another, so a score carries a name of its own. A mix-wide namespace can come later for convenience, if placing across scores feels awkward without it. What a pin takes is a query over the merged score that answers with a time, rerun while it is bound: a selector (key, score, the channels a voice writes, and tags a source attaches), an edge, and, where more than one voice matches, a reducer (next, first, last, earliest, latest). A key is the simplest selector; pin: { in: { before: { writes: 'gain', next: true }, by: 200 } } is fully in 200 ms before the next voice that writes gain. A selector reads only what the score knows — never a channel’s value, so “when gain crosses 0.5” is refused rather than searched for. The same queries answer what is playing at a time and where the next event is, which is where a read ahead splits its steps. A read ahead is a view: m.peek(t) returns one with sample(subject, out?) and sure(subject), which says per channel whether the answer is exact, stepped or held, the least sure voice that fed the channel deciding. A peek at an earlier reading throws until reading back exists. Undecided: whether a patch or signal that says nothing is taken as driven by the clock or by outside input, which decides whether an undeclared pointer read claims an exactness it did not earn or every existing fn patch reads held. A pin whose query has no answer yet — a key not cued, no voice matching, the out of a voice that loops for good — leaves the voice pending until it resolves; a cycle is refused at cue; and a pinned edge already past starts the voice partway through, the way playback starts in the middle of a region. A voice placed relative to another resolves against the mix’s merged view of every score it holds: it follows its target while that voice is there, however it is sought, faded or retimed, and keeps the time it last resolved to once the target leaves, whichever score the target belonged to.
  • The package name. blits is free on npm. @lightningjs/blits is a live TV app framework with its own animation plugin, so searches for the name land there first.
  • Color's lerp. The stock hex channel ships sRGB, which is what klieg's light channel assumes and what keeps the port's arithmetic identical. OKLCH reads better for a crossfade between hues and would replace it rather than join it; the choice waits on seeing a hue crossfade in the port.
  • Whether at writes into a buffer: no, it returns. A patch allocates one partial delta per subject per frame, and writes plus the fold order would let the mix hand it one scratch object instead. The port measured what that would buy: a frame of klieg’s motion — 12 letters through four voices — costs 0.017 ms, and a frame of its effects — 60 parts under three effects — costs 0.134 ms, against a 16.7 ms budget. Under 1% of a frame is not worth the nicest property at has, which is being a pure function a test calls once. The p99 of the effects frame is 1.3 ms, which is the collector catching up on exactly these allocations, so a subject count an order of magnitude past klieg’s would reopen it. packages/core/test/bench/frame-cost.bench.ts in klieg is the measurement
  • The stock band's width. Whether gate's default band is symmetric around at and how wide it is. It has to clear the frame noise in a real signal, so it is a measurement from klieg's near and dwell, not a guess.
  • Whether slew is linear or exponential. klieg's three decays are all linear, ms / rate, so linear keeps the port's arithmetic identical and the Playwright baselines green. An exponential release reads better and never reaches rest, which atRest needs it to, so it would want a floor. One choice, made once.
  • Whether magicsmoke wants this at all. Its fault is one intensity; the case is weakest there and it may stay a consumer only of slew.
